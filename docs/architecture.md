# Architecture

React + TypeScript + Vite, Recharts visualizations, Lucide icons and fflate ZIP parsing. A module Web Worker normalizes imports, deduplicates complete source rows, strips personal fields, and aggregates every filter/timezone query. The UI displays paginated track rows and bounded chart data. IndexedDB holds optional remembered workspaces or temporary OAuth checkpoints, entirely on the visitor's device.

`analytics.ts` is the metric contract, shared by the worker and unit tests. `spotify.ts` owns PKCE, token refresh, a bounded API client and bulk execution. `App.tsx` owns selection, reviewed actions, receipts and views. `components.tsx` contains chart and dialog presentation. `SpotifyWorkspace.tsx` owns the API-backed dashboard, filtered music selection and source-specific request state; `spotify-data.ts` normalizes API metadata and implements evidence-aware filters. The app shell is self-contained: no remote fonts, trackers, or CDN scripts.

The exported history and connected library are separate sources with separate freshness. Connecting does not backfill historical statistics. Music/podcast/audiobook and audio/video sources can be filtered separately. Historical charts attribute duration to end time. Returned artist genres can be filtered when present; session reconstruction and audio-feature enrichment are not implemented. The API workspace opens without a dataset, defaults to current data after sign-in, and shares the existing reviewed bulk executor with history selections.

Spotify secrets are not used. The public Client ID can be built into static assets. OAuth tokens are session-scoped, not included in URLs, screenshots, build output or source. Callback navigation cleans query parameters. State is one-use and expires after ten minutes. Stored workspaces are sanitized, and temporary checkpoints expire after one hour. Hosting sees static-asset requests; Spotify sees account authorization and selected library operations.

One shared Spotify app is configured by the site owner through `VITE_SPOTIFY_CLIENT_ID` at build/deployment time. Visitors go directly to Spotify authorization, with no developer setup or per-browser Client ID override. Missing or malformed deployment configuration leaves analytics available and presents a connection-unavailable message. Public hosting and Spotify authorization eligibility remain separate; development-mode users must be allowlisted by the app owner.

Failure semantics: library pagination errors propagate; partial reads are not presented as complete. Unknown mutation outcomes halt batches. Verified playlist membership is required before unliking. Rate-limit responses may be retried within bounded delays; ambiguous network/5xx writes are never retried automatically. The connected account is checked before a bulk operation or restore.

Hosting adapters should preserve a single stable HTTPS callback, SPA fallback routing, CSP and referrer protection. There is no database, server session or scheduler. Browser-local imports and authentication remain available only on that device/tab.

API sources have independent fetch timestamps and request generations. Older range/playlist/content responses cannot overwrite newer selections. Current library reads and playlist lists are committed together; failed pagination never yields an apparently complete partial collection. Missing ranking or recent evidence remains unknown and disables dependent filters. Returned recent events are deduplicated by track URI and timestamp, and are never treated as lifetime counts or actual listening duration. Playlist content reads are lazy; saved-content reads run for the selected category. Current playback refresh is opt-in, pauses when hidden and stops automatic refresh after an error.

Existing token scopes are retained through refresh. Missing read permissions prompt explicit reauthorization while leaving the current library usable. Scope checks avoid unauthorized insight requests. API quota-exceeded responses stop without automatic retries. Imported history still uses its own record cutoff and cannot override API library membership or current metadata.
